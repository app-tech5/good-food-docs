Backend API

The shared brain of the suite — one place for accounts, menus, orders, money rules, and live status so every app tells the same story.

Self-hosted One API for all apps Start this first

Who this product is for

Teams who own the marketplace end-to-end. You host the API (laptop, VPS, or cloud), keep the data, and decide how orders, wallets, and partners behave — instead of renting a black-box backend you cannot extend.

Buyers and PMs can read this page for the role of the API. Engineers follow Getting Started and the source markdown for env files, migrations, and boot order.

Why every other app depends on it

Customer, driver, restaurant, and admin are faces. The backend is the memory and the rules:

  • Identity — who is a customer, restaurant, driver, or admin
  • Catalog & cart — what can be sold and how checkout settles
  • Order lifecycle — kitchen → courier → delivered, visible everywhere
  • Money & market — plans, sponsorship, gateways, languages, taxes, fees

If the API is down, every polished front-end looks broken. Boot the server first, then open Expo or the admin site.

What it unlocks in the product docs

Feature pages for earnings, languages, recommendations, deliveries, and kitchen display all assume this API is running and seeded. Use those pages to understand what operators and end users see; use Getting Started (and source markdown) to understand how to turn the service on.
