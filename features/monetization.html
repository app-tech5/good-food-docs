Monetization

How the platform earns: commissions, subscriptions, sponsored listings, wallets, and multi-PSP checkout.

Commissions Subscriptions Sponsored ads Wallet & gateways

Overview

Good Food Pro is built as a marketplace you operate. Revenue is not limited to a single “delivery fee” field: the backend resolves commission splits, optional SaaS subscription benefits, paid placement (sponsored listings), and wallet / payment-gateway flows used by customers, restaurants, and drivers.

Commissions

Platform commission is computed per restaurant (or from a global default in app settings). Active restaurant subscriptions can reduce or waive that rate (commissionService.getEffectiveCommissionRate).

Order totals are split into platform vs restaurant shares with splitOrderAmounts. Admin earnings screens reflect those splits for ops and payouts.

Subscriptions (SaaS tiers)

Plans live in the subscriptions collection and target one of: customer, driver, or restaurant. Each plan has price, currency, billing cycle, benefit text, and machine-readable benefitFlags (free delivery, discounts, reduced commission, priority support, etc.).

  • API: /api/subscriptions
  • Apps: Subscriptions screens in Customer, Driver, and Restaurant apps
  • Admin: manage plans / user subscriptions as entities
  • Demo seeds: migrations 37, 42 (driver tiers), 43 (customer tiers)

Sponsored listings

Restaurants can buy paid placement (search / home-style placements) with bid, budget, schedule, and tracking (impressions / clicks). Active listings are served to the customer app; restaurants manage their own campaigns in Sponsored Listings.

  • API: /api/sponsored (active, mine, activate, track)
  • Model / service: SponsoredListing, sponsoredListingService
  • Demo seed: migration 39-saas-sponsored-seed.js

Wallet ledger

Customer wallet supports balance, cashback, and instant-refund style flows (flags in app settings from market-adaptability migration). Ledger logic lives in walletLedgerService; the customer app exposes wallet / add-money screens.

Payment gateways

Beyond Stripe Connect for marketplace payouts, the API exposes a multi-provider gateway surface:

  • API: /api/gateways — list providers, initialize a payment
  • Service: paymentGatewayService (regional PSPs such as Paystack, Flutterwave, Razorpay — plus Stripe)
  • Admin can manage gateway / earnings configuration used in demos and production setups

Related demo fill: migration 40-monetization-demo-fill.js.
