Market adaptability

Languages, currencies, hybrid order channels, and regional payment options so you can launch beyond one country.

EN · FR · ES · AR Multi-currency Channels Regional PSPs

Overview

Market adaptability means the same Pro stack can be branded and operated in different regions: UI locales (including RTL Arabic), currency display, optional hybrid channels (for example WhatsApp / USSD style entry points), wallet cashback defaults, and gateway slots for local processors.

Seed / defaults: migration 44-market-adaptability.js.

Languages

Backend languages collection includes English, French, Spanish (es), and Arabic (ar, RTL). Mobile apps and admin ship matching locale JSON files; the customer app can switch language locally for demos without forcing a backend write when that is not desired.

  • Customer / Driver / Restaurant: lang/en.json, fr.json, es.json, ar.json
  • Admin: src/locales/ (same codes)
  • Backend: src/locales/ + i18n config

See also Environment setup — Languages.

Currencies

App currency is configured in settings (documented under Change app currency). Admin can manage currency entities for multi-market dashboards.

Hybrid channels

Channel APIs let you expose marketplace entry points beyond the native apps (for example messaging or USSD-oriented flows), while orders still land in the same MongoDB order pipeline.

  • API: /api/channels (public + protected routers)
  • Service: channelService
  • Admin: channel-related fields / entities for ops configuration

Regional payments & wallet defaults

Migration 44 turns on wallet cashback / instant-refund flags and prepares gateway slots for regional PSPs (used with /api/gateways). Combine with Stripe Connect where card marketplace payouts are required.
