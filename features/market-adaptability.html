Market adaptability

Food delivery is local. Language, currency, how people pay, and how orders arrive all change from city to city. This platform is built so you can feel local without rewriting the product for every launch.

Languages Currencies Channels Regional payments

Speak the way your city speaks

English, French, Spanish, and Arabic ship across customer, driver, restaurant, admin, and the API — including right-to-left where Arabic needs it. Users switch language in settings; admin controls which languages are active and which is default.

Customer — language picker

Admin — enable languages and set the default

Price in the currency people expect

Menus, carts, wallets, and reports follow the currency you configure. Change the default when you expand; partners and customers always see numbers that make sense locally.

Admin currencies — set once, use across apps

Hybrid channels, one order brain

Not every order starts in the mobile app. Counter, phone, or partner channels can still land in the same kitchen and courier flow. One order pipeline keeps status, earnings, and logistics consistent — so you do not run two disconnected systems.

Admin settings — marketplace behaviour in one place

Payments and wallet habits that fit the region

Card rails, regional PSPs, and wallet behaviours (cashback, smoother refunds) are part of feeling local. See also Monetization for commissions, plans, ads, wallet, and gateways.
