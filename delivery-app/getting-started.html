Getting Started

Put a courier online against your API, accept a first job, and complete a delivery with proof when your rules require it.

Driver app First shift Android & iOS

What you will achieve

A working driver session: sign in as a courier, go available, see assignable jobs, and finish at least one drop-off. That proves last-mile, live tracking for the customer, and proof of delivery in one loop.

Terminal commands, config keys, and map/location notes are in source-docs/delivery-app/getting-started.md. This page is the orientation for buyers and ops leads.

Before you open the driver app

  1. Shared tooling installed — Environment setup.
  2. API running — Backend — Getting Started.
  3. A user with the driver role (customer-only accounts are rejected at login).
  4. Ideally: a restaurant-ready order waiting so a job can appear after you go online.

Soft path to first job

  1. Open the driver project from the suite ZIP.
  2. Install dependencies and point the app at the same API base as customer / restaurant / admin.
  3. Install a development build once (Expo Go is not supported here), then start Metro for later sessions.
  4. Sign in as a driver, allow location when prompted, go online.
  5. Accept a job (or a nearby batch), navigate, then complete with photo / signature when required.

Exact env lines, demo driver credentials, and troubleshooting (“no jobs”) are in the source markdown — including radius / accept state checks covered further in the logistics guide.

After it runs — what to explore

  • Job board & batching · On the road · Photo & signature POD
  • Shift earnings · Payouts & history
  • Priority plans · Languages & RTL
  • Live tracking — customer view of the same order

Full suite smoke test: source-docs/00-launch-suite.md. Deeper POD / batching: source-docs/delivery-app/logistics.md.
