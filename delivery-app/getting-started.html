Getting Started

Launch the driver app with the same gentle, step-by-step style as the customer app—even if this is your first mobile project.

Goal: install tools, connect to your API, and complete one successful login as a driver. You will need a user account that is registered as a courier on the server (not only a customer).

1) Prerequisites

Before the driver app can run, you need a few free tools on your computer. This section explains each one in plain language. Follow the steps for your operating system; you can always come back if something fails the first time.

Important: Start your Good Food backend (for example the my-backend project) before opening the driver app. The mobile app only shows real data when the server is online and reachable from your phone or emulator.
Driver account: The email you use to log in must belong to someone your backend recognizes as a driver. If you try a normal customer account, the app may refuse login after the password step. Create or promote a test driver in your database or admin tools first.

Install Node.js LTS, Expo tooling, and Android Studio / Xcode using the shared guide: Environment setup → Node.js and Expo and native tooling. When the app asks for location access, allow it if you want maps and GPS-based features.

2) Step-by-step installation

  1. Open a terminal.
  2. Go to the delivery-app folder (the same level as package.json).
  3. Run npm install and wait until it finishes without red errors.
  4. Confirm your backend is still running and that you know the API URL you will paste into config.

When this completes, your computer has everything the project needs to start in development mode.

Install dependencies delivery-app 
cd delivery-app
npm install

3) Configuration & personalization

The driver app keeps its settings in one file at the root of the project: config.js. (The customer app uses config/index.js—different path, same idea.)

API address

The line that matters most is API_BASE_URL. It must match the address where your backend listens, usually ending with /api exactly as your server expects.

config.js (excerpt) 
# Prefer .env (see .env.example)
EXPO_PUBLIC_API_URL=http://YOUR_SERVER_IP:5000/api
EXPO_PUBLIC_DEMO_MODE=true
EXPO_PUBLIC_DEMO_EMAIL=driver@demo.com
EXPO_PUBLIC_DEMO_PASSWORD=driver123

# config.js
APP_NAME: 'Good Food Pro Driver',
VERSION: '1.0.0',
API_TIMEOUT: 10000

Login uses POST /auth/delivery-login. Use the same host and port as the customer app. If the port in your backend is different (for example 8080), change the URL accordingly.

Demo mode

When DEMO_MODE is true, the login screen can be pre-filled with sample credentials—handy for demos. Before a real release, set it to false and rely on real courier accounts.

Languages (EN/FR/ES/AR, lang/, i18n.js): see Environment setup → Languages (i18n).

Look and feel

Colors and shared styles are centralized in global.js. Adjust them there if you want the driver app to match your brand.

Change app name

In delivery app, rename the Expo label and the runtime labels used in login/settings logic.

app.json (delivery-app) 
{
  "expo": {
    // Replace with your public app label
    "name": "YOUR_DELIVERY_APP_NAME",
    "slug": "your-delivery-app-slug",
    "ios": {
      "bundleIdentifier": "com.yourcompany.yourdeliveryapp"
    },
    "android": {
      "package": "com.yourcompany.yourdeliveryapp"
    }
  }
}
config.js (visible title in screens) 
export const config = {
  // Replace with the in-app label you want
  APP_NAME: 'YOUR_DELIVERY_APP_NAME',
  VERSION: '1.0.0'
}
utils/settingsUtils.js (fallback name) 
export const DEFAULT_APP_NAME = 'YOUR_DELIVERY_APP_NAME'
Tip: After editing config.js or theme files, stop and restart npm start so the bundler picks up changes.

Logo update

Update only the logo image file in assets/images and keep the same file name. Do not change paths or configuration when you only want a new logo.

  1. Open the app logo file in assets/images inside delivery-app.
  2. Replace the image with your own logo.
  3. Keep exactly the same filename.
  4. Restart the app.

Default currency for the whole platform (admin + mobile) is documented here: Environment setup → App currency (change).

Maps

The driver app uses MapLibre (not Google Places). No Google Maps API key is required in config.js for the default map experience.

4) API connection checklist

The driver app contacts your server for sign-in (POST /auth/delivery-login), order lists, profile updates, and settings—driver-specific endpoints on the same REST API as the rest of the suite.

For a basic test you only need the correct URL in .env / config.js. Device vs localhost is covered on Environment setup → API reachability.

5) Run the project

Expo Go is not supported. Install a development build first (expo-dev-client + MapLibre + background location).
  1. Backend running, .env set from .env.example, npm install already done.
  2. First time: npm run android or npm run ios.
  3. Later: npm start, then open the installed Good Food Pro Driver app.
  4. Sign in with demo driver@demo.com / driver123 (or your seeded driver); open Home, Deliveries, and Profile.
Run commands Expo 
cp .env.example .env
npm run android   # first time: development build
npm start           # later: Metro only
