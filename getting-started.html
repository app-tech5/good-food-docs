Getting Started

Get the customer storefront running against your API, sign in once, and place a first test order.

Customer app First launch Android & iOS

What you will achieve

By the end of this path you can open the customer app on a phone or emulator, reach your marketplace API, browse restaurants, and complete a small order. That is the smoke test buyers and agencies use before branding or store builds.

Commands, env variable names, and device networking quirks live in the source markdown that ships with the ZIP (and are mirrored under this docs repo’s source-docs/). This page stays on the journey — not a second copy of those terminal steps.

Before you open the customer app

  1. Install the shared tooling once (Node, Android and/or iOS tools) — see Environment setup.
  2. Start the Backend API and confirm it answers — Backend — Getting Started.
  3. Have a customer account ready (seeded demo user or one you created in admin).

If the API is down, login and menus fail even when the mobile install looks perfect. Always boot the server first.

Soft path to first login

  1. Open the customer app project from your suite ZIP.
  2. Install dependencies, then point the app at the same API URL the rest of the suite uses (including the /api path when required).
  3. Build a development client the first time (Expo Go is not enough for this stack), then start the bundler for later sessions.
  4. Sign in as a customer and land on home / discovery.
  5. Place a small order; complete the loop later with restaurant accept + driver delivery.

Exact npm / .env lines, simulator vs physical phone URLs, and demo credentials: see source-docs/customer-app/getting-started.md in the pack (also in this repo under source-docs/).

After it runs — what to explore
