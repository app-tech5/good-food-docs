Getting Started

Open the operator console in a browser, sign in as admin, and confirm the marketplace settings your mobile apps will obey.

Admin web First login Desktop

What you will achieve

A working admin session: dashboard loads, lists show seeded data, and you can open App Settings, languages, currencies, subscriptions, and orders — the cockpit before you invite real restaurants or run a full city.

Env variable names, build/start commands, and branding file paths are in source-docs/admin-app/getting-started.md.

Before you open the admin app

  1. Node tooling installed — Environment setup.
  2. API running with migrations applied — Backend — Getting Started.
  3. An admin-capable account from seed / your own create step.

Admin only shows what the API allows for that role. Wrong URL or stopped server looks like “empty console,” not a UI bug.

Soft path to first console session

  1. Open the admin project from the suite ZIP.
  2. Install dependencies and point the web app at your API (base URL + server URL as documented in the markdown).
  3. Start the local web server and open the URL in a desktop browser.
  4. Sign in, land on the dashboard, open Orders / Restaurants / Settings to confirm data loads.
  5. Align languages, currency & taxes, and gateways before a public demo — then try a full order with the mobile apps.

After it runs — what to explore

  • Orders & support · Partners & users · Menus & catalog
  • Commissions & earnings · Subscription plans · Payment gateways
  • Promo campaigns · Coupon codes · Order channels
  • Languages & RTL · Sales analytics · Money ledger
