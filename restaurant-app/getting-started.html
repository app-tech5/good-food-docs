Getting Started

Connect the partner app to your API, accept a first order, and open the kitchen board when you are ready for service.

Restaurant app First accept Android & iOS

What you will achieve

Staff can sign in as a restaurant, see live incoming tickets, accept (or reject) with confidence, and optionally run Kitchen Display on a tablet at the pass — all against the same order the customer just placed.

Live vs demo scripts, env keys, and first-accept troubleshooting are in source-docs/restaurant-app/getting-started.md.

Before you open the restaurant app

  1. Tooling ready — Environment setup.
  2. API up — Backend — Getting Started.
  3. A restaurant user tied to the correct restaurant on the API.
  4. Prefer live mode against your API when you want real orders (demo mode is for empty presentations only).

Soft path to first accept

  1. Open the restaurant project from the suite ZIP.
  2. Install dependencies and point the app at the shared API URL.
  3. Install a development build once, then use the bundler for later sessions.
  4. Sign in, keep the restaurant open for service, watch the orders list.
  5. From the customer app, place an order; here, accept it — that unlocks KDS tickets and driver assignment.

After the first accept, open Kitchen Display, menu edits, subscriptions, and sponsored listings from the drawer — those flows are documented on the feature pages and in source markdown (KDS + monetization).

After it runs — what to explore

  • Orders & menu
  • Kitchen Display (KDS)
  • Subscriptions
  • Sponsored listings

Suite checklist: source-docs/00-launch-suite.md. KDS detail: source-docs/restaurant-app/kitchen-display.md.
